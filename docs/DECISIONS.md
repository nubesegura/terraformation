# Design decisions (short ADR)

> 🇪🇸 Versión en español: [docs-es/DECISIONS.md](../docs-es/DECISIONS.md)

Every decision on an ambiguity favors the simplest, safest and cheapest option.

| # | Decision | Rationale |
|---|----------|-----------|
| D1 | Python 3.13, arm64, **Pydantic v2** for all models (state, DynamoDB, API) and **FastAPI + Mangum** for the HTTP API | FastAPI generates the OpenAPI contract, Pydantic validates. arm64 is cheaper. |
| D2 | A single `terraformation` package (`backend/src` folder) built once and shared by all Lambdas (each with its own `Handler`) | One artifact, one `pip install`; avoids layers with account/region ARNs. Powertools is packaged as a dependency. |
| D3 | The API is **FastAPI** in a Lambda behind an **HTTP API**; the JWT is validated by the HTTP API's **native JWT authorizer** with Cognito (no Lambda authorizer) | Free, no code to maintain, smaller surface. |
| D4 | Data unit = **state = (project, workspace)**. Key `p/<file>` → workspace `default`; `env:/<ws>/p/<file>` → workspace `<ws>`. The `env:` prefix is never interpreted as a project. A state at the bucket root (no project) is ignored | Follows the described convention and the real layout of Terraform's S3 backend. |
| D5 | PK `PROJECT#<project>#<workspace>` (the workspace is always present) | Avoids ambiguity; a single key pattern. |
| D6 | Single table `terraformation-<env>` with 2 GSIs; minimal provisioned capacity by default (5/5 table, GSIs 2/5 → within the 25 WCU/25 RCU free tier); `BillingMode` configurable to on-demand | Requested. A large backfill is best done with temporary on-demand. |
| D7 | The raw state is **never** stored: DynamoDB keeps parsed metadata + a `bucket/key/versionId` reference. A version's detail, the graph and the diff are computed **on demand by reading S3 by versionId** and parsing/masking in memory | Avoids the 400 KB limit, saves WCU and keeps secrets out of the database. |
| D8 | Resource items (search) are stored **only for the current version** of each state; the history is made of light `VERSION#` items with change counts | Cost: writing resources for every version would multiply WCU. Documented limitation: search covers the current version. |
| D9 | Resource items are only rewritten when their `content_hash` changes (computed over already masked content) | Reduces WCU. |
| D10 | Idempotency: the existence of the `VERSION#<LastModified>#<versionId>` item (written last with `attribute_not_exists` in a transaction together with the counters) is the idempotency record (bucket/key/versionId). All earlier steps are idempotent | No extra table. Duplicates and retries are safe. |
| D11 | Ordering: the "current" state is the one with the highest `(LastModified, serial, versionId)`; summary updates are conditional. An out-of-order version is recorded in the history, recalculates its successor's counts and does not touch the current one | Requested (LastModified and serial). |
| D12 | Failures: EventBridge → Lambda with `RetryPolicy` + `DeadLetterConfig` (SQS) on the target, and `EventInvokeConfig` (2 retries, `OnFailure` → same SQS) on the Lambda. One shared DLQ, SSE-SQS, 14-day retention, alarm when it has messages | Covers delivery and execution failures. |
| D13 | **Locks**: each `.tflock` event is only a *trigger*; the Lambda reads the event version's JSON and rebuilds the state with `ListObjectVersions(Prefix=<key>)` (`IsLatest`: version ⇒ locked, delete marker ⇒ released). Idempotent and immune to duplicate or out-of-order events | More robust than keeping an event-driven state machine. |
| D14 | `Object Deleted` with `deletion-type = Permanently Deleted` on a `.tflock` (e.g. lifecycle expiration of non-current versions) does **not** release the lock or delete history | With the recommended lifecycle rule these events arrive; they would release locks by mistake. |
| D15 | `.tfstate` delete markers are stored as history entries (`kind=delete_marker`) and flag the state as `deleted`; permanently deleting a version removes it from the history and the state is refreshed | Covers `delete marker`. |
| D16 | `ingest`, `backfill` and `reconcile` share the same engine (`sync`). Backfill and reconcile process key by key in ascending order, skip already registered versions and **reinvoke themselves** with a cursor before running out of time | One code path, resumable, no Step Functions. |
| D17 | `.tflock` files are never treated as state (strict regex on the exact configured name suffix; the `.tflock` suffix is excluded by construction) | Requested. |
| D18 | Notifications custom resource: reads the current configuration, keeps the Topic/Queue/Lambda configurations and sets `EventBridgeConfiguration: {}`; on `Delete` it **does nothing** (EventBridge is not disabled, other consumers may depend on it) unless `DisableOnDelete=true`. Manual alternative: `ManageBucketNotifications=false` + `scripts/enable-eventbridge.sh` | Safety: do not destroy foreign config. |
| D19 | The EventBridge event `key` is used as is (not URL-decoded) | Unlike classic notifications, EventBridge delivers the key unencoded. |
| D20 | Masking at ingestion: the state's `sensitive_attributes` + value patterns (AWS keys, PEM private keys, JWT, GitHub/Slack tokens…) + heuristic by attribute name (`password`, `secret`, `token`, `private_key`…). `sensitive` outputs → `(sensitive)`. Changes in sensitive values are detected with a digest kept **in memory only** (`sensitive_changed`), never persisted | Security without losing change detection. |
| D21 | Attributes are flattened to `dotted.key` (`tags.Name`, `ebs.0.size`), nulls omitted, values truncated (1 KB in DynamoDB, 4 KB in the API) | Compatible with terraboard's search and with the item size limit. |
| D22 | Search: by type → GSI1, by name → GSI2, by project → Query by PK; an attribute alone with no other filter → filtered, bounded `Scan` | Cheap for small workloads; documented limitation. |
| D23 | **Provider** versions: the v4 state does not contain them; the providers in use (source address) are shown and, if plans are sent, the `version_constraint` | Honesty about what the data allows. |
| D24 | Optional `POST /api/plans` (`EnablePlansApi`, off by default), same payload as terraboard. A per-resource change summary is stored (not the raw `plan_json`). Authorization: JWT with scope `terraformation/plans.write` (*client_credentials* client for CI) | Avoids secrets and the 400 KB limit. |
| D25 | Cognito: pool with `AdminCreateUserOnly`, managed login domain, SPA client with Authorization Code + PKCE and no secret. Users are created through the Makefile | No self sign-up. |
| D26 | Flutter web frontend, private S3 + CloudFront with OAC, `*.cloudfront.net` domain (no ACM/Route53). The configuration (`config.json`) is published from the stack outputs | No circular dependency or domain cost. |
| D27 | CORS restricted to the CloudFront domain (+ optional extra origins for development) | Requested. |
| D28 | Optional Bedrock summary (`EnableBedrockSummary=false`); only resource addresses and already masked, truncated keys/values are sent; IAM `bedrock:InvokeModel` only when enabled. The summary language follows the UI language (`language` field) | Privacy and cost. |
| D29 | Encryption: SSE with AWS-managed keys (DynamoDB owned key, SQS-SSE, S3 SSE-S3, logs without KMS) | Avoids KMS cost. |
| D30 | Deployment with **SAM transform + nested stacks** packaged and deployed with `sam package` / `sam deploy` (no `sam build`; the code is built by `scripts/build_lambda.sh`) | One shared artifact. `aws cloudformation package` ignores SAM `Globals` and packaged the Lambdas wrongly (see history). |
| D31 | Gitflow: `main` (production), `develop`, `feature/*`, `release/*`, `hotfix/*`. GitHub `dev`/`prod` environments with variables and secrets; configured manually by the repository owner → steps in `docs/GITFLOW.md` | Repository administration is done by the owner. |
| D32 | `.tflock` lifecycle: S3 **cannot filter by suffix** and mixing a size filter could expire small `.tfstate` versions (an empty state weighs ≈ the same as a lock). The recommended rule uses the lock's **exact key** (`<project>/terraform.tfstate.tflock`) as `Prefix`, which is not a prefix of any `.tfstate`. It is generated with `scripts/lifecycle_tflock.py` from the states' keys | Satisfies "never touch .tfstate versions". Also, the lock history is already in DynamoDB, so expiration is only hygiene. The resulting `Permanently Deleted` events do not release locks (D14). |
| D33 | Powertools Logger/Tracer in every Lambda; `POWERTOOLS_TRACE_DISABLED` follows the `EnableXRay` parameter | Optional tracing at no cost by default. |
| D34 | CloudFormation: one root stack + 4 nested (`storage`, `web`, `ingestion`, `api`); `checkov` with no findings (justified skips in `Metadata`) and custom `cfn-guard` rules in `infra/guard` | Requested. |
| D35 | English is the default language everywhere (code, API messages, docs). The frontend ships a hand-rolled EN/ES i18n (`lib/l10n`), switchable at runtime with a button and persisted in `localStorage`; the original Spanish documentation lives in `docs-es/` | Wider reach; no extra dependency, and a missing translation is a compile error. |
