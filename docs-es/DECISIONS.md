# Decisiones de diseño (ADR resumido)
> 🇬🇧 English version (primary): [../docs/DECISIONS.md](../docs/DECISIONS.md)

Cada decisión ante una ambigüedad prioriza lo más simple, seguro y económico.

| # | Decisión | Justificación |
|---|----------|---------------|
| D1 | Python 3.13, arm64, **Pydantic v2** para todos los modelos (state, DynamoDB, API) y **FastAPI + Mangum** para la API HTTP | FastAPI genera el contrato OpenAPI, Pydantic valida. arm64 es más barato. |
| D2 | Un único paquete `terraformation` (carpeta `backend/src`) empaquetado una sola vez y compartido por todas las Lambdas (cada una con su `Handler`) | Un solo artefacto, un solo `pip install`; evita capas con ARN de cuenta/región. Powertools se empaqueta como dependencia. |
| D3 | La API es **FastAPI** en una Lambda detrás de **HTTP API**; el JWT lo valida el **authorizer JWT nativo** de HTTP API con Cognito (sin Lambda authorizer) | Gratis, sin código que mantener, menos superficie. |
| D4 | Unidad de datos = **state = (proyecto, workspace)**. Clave `p/<archivo>` → workspace `default`; `env:/<ws>/p/<archivo>` → workspace `<ws>`. El prefijo `env:` nunca se interpreta como proyecto. Un state en la raíz del bucket (sin proyecto) se ignora | Respeta la convención descrita y el layout real del backend S3 de Terraform. |
| D5 | PK `PROJECT#<proyecto>#<workspace>` (el workspace siempre presente) | Evita ambigüedades; un solo patrón de claves. |
| D6 | Tabla única `terraformation-<env>` con 2 GSI; capacidad provisionada mínima por defecto (5/5 tabla, GSIs 2/5 → dentro de 25 WCU/25 RCU free tier); `BillingMode` configurable a on-demand | Pedido. El backfill grande se recomienda con on-demand temporal. |
| D7 | **Nunca** se guarda el state crudo: DynamoDB guarda metadatos parseados + referencia `bucket/key/versionId`. El detalle de una versión, el grafo y el diff se calculan **bajo demanda leyendo S3 por versionId** y parseando/enmascarando en memoria | Evita el límite de 400 KB, ahorra WCU y evita secretos en la base. |
| D8 | Los ítems de recurso (búsqueda) se guardan **solo para la versión vigente** de cada state; el historial son ítems `VERSION#` ligeros con conteos de cambios | Costo: escribir recursos de cada versión multiplicaría WCU. Documentado como limitación: la búsqueda cubre la versión actual. |
| D9 | Los ítems de recurso solo se reescriben si cambia su `content_hash` (calculado sobre contenido ya enmascarado) | Reduce WCU. |
| D10 | Idempotencia: la existencia del ítem `VERSION#<LastModified>#<versionId>` (escrito al final con `attribute_not_exists` en una transacción junto con los contadores) es el registro de idempotencia (bucket/key/versionId). Todos los pasos previos son idempotentes | Sin tabla extra. Duplicados y reintentos son seguros. |
| D11 | Orden: el estado "vigente" es el de mayor `(LastModified, serial, versionId)`; las actualizaciones del resumen son condicionales. Una versión fuera de orden se registra en el historial, recalcula los conteos de su sucesor y no toca la vigente | Pedido (LastModified y serial). |
| D12 | Fallos: EventBridge → Lambda con `RetryPolicy` + `DeadLetterConfig` (SQS) en el target, y `EventInvokeConfig` (2 reintentos, `OnFailure` → misma SQS) en la Lambda. Una cola DLQ compartida, SSE-SQS, retención 14 días, alarma si hay mensajes | Cubre fallo de entrega y de ejecución. |
| D13 | **Locks**: cada evento `.tflock` solo es un *disparador*; la Lambda lee el JSON de la versión del evento y reconstruye el estado con `ListObjectVersions(Prefix=<key>)` (`IsLatest`: versión ⇒ bloqueado, delete marker ⇒ liberado). Es idempotente e inmune a eventos duplicados o desordenados | Más robusto que mantener una máquina de estados por eventos. |
| D14 | `Object Deleted` con `deletion-type = Permanently Deleted` sobre un `.tflock` (p. ej. expiración por lifecycle de versiones no actuales) **no** libera el lock ni borra historial | Con la regla de lifecycle recomendada llegan estos eventos; liberarían locks por error. |
| D15 | Delete markers de `.tfstate` se guardan como entradas de historial (`kind=delete_marker`) y marcan el state como `deleted`; el borrado permanente de una versión la elimina del historial y se refresca el state | Cubre `delete marker`. |
| D16 | `ingest`, `backfill` y `reconcile` comparten el mismo motor (`sync`). Backfill y reconcile procesan por key en orden ascendente, se saltan versiones ya registradas y se **auto-reinvocan** con un cursor antes de agotar el tiempo | Un camino de código, reanudable, sin Step Functions. |
| D17 | Los `.tflock` jamás se tratan como state (regex estricta por sufijo exacto del nombre configurado; el sufijo `.tflock` queda excluido por construcción) | Pedido. |
| D18 | Custom resource de notificaciones: lee la configuración actual, conserva Topic/Queue/Lambda configurations y fija `EventBridgeConfiguration: {}`; en `Delete` **no hace nada** (no se desactiva EventBridge, otros consumidores podrían depender) salvo `DisableOnDelete=true`. Alternativa manual: `ManageBucketNotifications=false` + `scripts/enable-eventbridge.sh` | Seguridad: no destruir config ajena. |
| D19 | El `key` del evento de EventBridge se usa tal cual (no URL-decoded) | A diferencia de las notificaciones clásicas, EventBridge entrega el key sin codificar. |
| D20 | Enmascarado en ingesta: `sensitive_attributes` del state + patrones de valores (AWS keys, claves privadas PEM, JWT, tokens de GitHub/Slack…) + heurística por nombre de atributo (`password`, `secret`, `token`, `private_key`…). Outputs `sensitive` → `(sensitive)`. Cambios en valores sensibles se detectan con un digest **solo en memoria** (`sensitive_changed`), nunca persistido | Seguridad sin perder detección de cambios. |
| D21 | Atributos se aplanan a `clave.punteada` (`tags.Name`, `ebs.0.size`), nulos omitidos, valores truncados (1 KB en DynamoDB, 4 KB en la API) | Compatible con la búsqueda de terraboard y con el límite de ítem. |
| D22 | Búsqueda: por tipo → GSI1, por nombre → GSI2, por proyecto → Query por PK; solo atributo sin otro filtro → `Scan` filtrado y acotado | Barato para cargas pequeñas; limitación documentada. |
| D23 | Versiones de **providers**: el state v4 no las contiene; se muestran los providers en uso (source address) y, si se envían planes, los `version_constraint` | Honestidad sobre lo que los datos permiten. |
| D24 | `POST /api/plans` opcional (`EnablePlansApi`, desactivado por defecto), mismo payload que terraboard. Se guarda un resumen de cambios por recurso (no `plan_json` crudo). Autorización: JWT con scope `terraformation/plans.write` (cliente *client_credentials* para CI) | Evita secretos y límite de 400 KB. |
| D25 | Cognito: pool con `AdminCreateUserOnly`, dominio managed login, cliente SPA con Authorization Code + PKCE sin secreto. Usuarios se crean por Makefile | Sin auto-registro. |
| D26 | Frontend en Flutter web, S3 privado + CloudFront con OAC, dominio `*.cloudfront.net` (sin ACM/Route53). La configuración (`config.json`) se publica desde los outputs del stack | Sin dependencia circular ni costo de dominio. |
| D27 | CORS restringido al dominio CloudFront (+ orígenes extra opcionales para desarrollo) | Pedido. |
| D28 | Resumen con Bedrock opcional (`EnableBedrockSummary=false`); solo se envían direcciones de recursos y claves/valores ya enmascarados y truncados; IAM `bedrock:InvokeModel` solo si está activo | Privacidad y costo. |
| D29 | Cifrado: SSE con claves administradas por AWS (DynamoDB owned key, SQS-SSE, S3 SSE-S3, logs sin KMS) | Evita costo KMS. |
| D30 | Despliegue con **SAM transform + nested stacks** empaquetado y desplegado con `sam package` / `sam deploy` (sin `sam build`; el código lo construye `scripts/build_lambda.sh`) | Un artefacto compartido. `aws cloudformation package` ignora `Globals` de SAM y empaquetó mal las Lambdas (ver historial). |
| D31 | Gitflow: `main` (producción), `develop`, `feature/*`, `release/*`, `hotfix/*`. Environments de GitHub `dev`/`prod` con variables y secrets; configurados manualmente por el dueño del repositorio → pasos en `docs/GITFLOW.md` | La administración del repo la hace el dueño. |
| D32 | Lifecycle de `.tflock`: S3 **no permite filtrar por sufijo** y mezclar un filtro por tamaño podría expirar versiones pequeñas de `.tfstate` (un state vacío pesa ≈ lo mismo que un lock). La regla recomendada usa como `Prefix` la **key exacta** del lock (`<proyecto>/terraform.tfstate.tflock`), que no es prefijo de ningún `.tfstate`. Se genera con `scripts/lifecycle_tflock.py` a partir de las keys de los states | Cumple “jamás tocar versiones de .tfstate”. Además el historial de locks ya está en DynamoDB, así que la expiración solo es higiene. Los eventos `Permanently Deleted` resultantes no liberan locks (D14). |
| D33 | Powertools Logger/Tracer en todas las Lambdas; `POWERTOOLS_TRACE_DISABLED` sigue al parámetro `EnableXRay` | Trazado opcional sin costo por defecto. |
| D34 | CloudFormation: un stack raíz + 4 nested (`storage`, `web`, `ingestion`, `api`); `checkov` sin hallazgos (omisiones justificadas en `Metadata`) y reglas propias `cfn-guard` en `infra/guard` | Pedido. |
